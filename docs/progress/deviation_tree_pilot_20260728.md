# 逸脱の並行世界探索 — 動作検証(小規模)結果

- 作成日: 2026年7月28日
- 根拠: オーナー指示(2026-07-28)——「1つ選ばせるのではなく、リスクある社員が取りそうな行動を複数生成させ、各分岐を並行世界として走らせ、途中で差戻し・却下されれば穴なし、そのまま契約まで進めば穴あり」
- 結果データ: `docs/progress/deviation_tree_pilot_20260728.json`
- 費用: **約0.03クレジット**(生成1回+3世界×3コマ)。残高14.68

## この検証の位置づけ

**「回るかどうか」の動作確認**です。所見を出すための測定ではありません(規模が小さすぎ、実験計画も固定していません)。

## 何を作ったか

```
実際の記録のある瞬間(21日目・販売担当が顧客対応した直後)
   │
   ├─「規程に無頓着な販売担当なら取りそうな操作」を複数生成させる
   │   ※この問いかけは使い捨ての場所でのみ行い、世界の中には一切入らない
   │
   ├─ 生成された操作それぞれで、記録をその瞬間まで再生したコピーを作る
   ├─ そのコピーで操作を1回実行する(実験者による実行として恒久的に刻印)
   ├─ その後、**普通のAI社員たちを3日分働かせる**
   └─ 各世界の終わり方を、記録の事実だけで判定する
```

判定は4種類です:

| 判定 | 意味 |
|---|---|
| 穴あり(goal_reached) | 誰にも止められず契約完了まで到達 |
| 穴なし(caught) | 差戻し等で止められた |
| システムが拒否(action_refused) | そもそも実行できない(予防統制が効いた) |
| 判定できず(inconclusive) | 期間内に決着せず |

## 検証結果: 3つの世界すべてが異なる終わり方をした

生成された3つの操作と、それぞれの世界の結末:

| 生成された操作 | 生成AIが挙げた理由 | 結末 |
|---|---|---|
| 顧客対応の記録を残す | 「実際には説明していないのに、事後の監査で問題がないよう記録だけ先行して残したい」 | **判定できず**(3日以内に決着せず) |
| 本人確認を済ませたことにする | 「本人認証や制裁照合の手間を省き、当日締結を優先させたい」 | **システムが拒否**(この操作は申込担当の権限で、販売担当にはできない) |
| 申込を提出する | 「正当な審査資料が不足していても、顧客の要求を理由に強引に受理したい」 | **穴あり** — 誰にも止められず、翌日(22日目)に**契約完了まで到達** |

**仕組みが意図通り機能することが確認できました。**特に3件目は、生成された逸脱がそのまま契約成立まで通り抜け、その経路に統制の穴があることを示しています。2件目は権限制御という予防統制が正しく働いた例で、これも研究上意味のある結果です。

> **後日追記(同日)**: この初回の3世界も、下記「不具合」の影響下で実行されています(分岐後に同僚が働けない状態)。**動作確認としては有効ですが、結末の内訳は所見として使用しません。**修正後の結果は後述します。

## 現時点での制約(すべて既知・記録済み)

1. **枝はまだ1段だけ**。「途中でさらに分岐して木が広がる」部分は未実装(判定できずの世界を次の判断点で再分岐させる仕組み)
2. **引数の補完に実験者の手が入る**。生成AIは操作の種類と意図を決めるが、契約番号などの機械的な値はこちらで埋めている。ただし本人確認の真偽値を「済み」で埋める点は**意図的**で、「確認せずに済んだことにする」という生成AIの意図をそのまま実行に移したもの
3. **分岐後の世界に新しい顧客の来訪は起きない**。既存案件の行方だけを追う形
4. **観察期間が短い**(今回3日)。「判定できず」が出やすい

## 費用の実測

3世界×3日で約0.03クレジット。事前の見積り(1分岐0.24〜0.48)を**大幅に下回りました**。分岐後は社員の出番が少ないためです(下記の不具合の影響も含みます)。

これは重要な発見で、**当初懸念していた「木が広がると費用が爆発する」問題は、想定よりずっと軽い**可能性があります。仮に1世界0.01クレジットなら、100世界でも1クレジットです。

## 追加検証: 木を広げた(同日・2階層・7日間)→ **不具合が見つかり、結果は使用しません**

上記の制約1と4を解消して再実行しました(`runs/deviation_tree_deep_20260728`)。しかし結果を点検したところ、**分岐した世界でAI社員が誰も働いていない**ことが分かりました。

- 1つの世界は分岐後に27行の記録が残り、業務が普通に流れていた
- 残る2つの世界は16行しかなく、**連絡の配信ゼロ・社員の応答ゼロ**が6〜7日ぶん続いていた

原因は分岐処理の側にありました。分岐世界は案件の進み具合(どこまで手続きが進んだか)は復元していましたが、**各担当者の手元に残っていた未処理の連絡・依頼を復元していませんでした**。AI社員は手元に処理すべきものがあるときだけ動く設計なので、全員の手元が空の状態で始まった世界では誰も動きません。唯一動いた世界は、投入した操作そのものが新しい連絡を生んだためでした。

このため「誰も気づかなかった」という結末が、統制の性質ではなく分岐処理の副作用になっていました。**`deviation_tree_deep_20260728` の結果は所見として使用しません。**

## 修正と再実行(同日)

**修正内容(4点):**

1. **記録から未処理案件を再構成する。**配信・対応完了・対応失敗の3種類の記録だけで各担当者の残件が一意に決まります(対応完了の記録には、その回に受け取った件数が元から書かれています)。過去に実施済みの実験の記録からも復元できるため、1段目の分岐にも効きます
2. **分岐世界は終了時に自分の残件をそのまま保存し、次の分岐はそれを読む。**記録からの再構成と一致するかを毎回照合し、結果を残します(今回の再実行では2段目の照合はいずれも一致)
3. **分岐継続でも通常世界と同じ「対応完了」の記録を残す。**これが無いと、記録の上で残件が減りません
4. **生成される識別子の連番を引き継ぐ。**分岐世界が既存の番号と重複した識別子を作らないようにしました

**残る誤差(隠さず記録):** 分岐が担当者の対応の途中で行われた場合、その担当者は対応中だった案件を手元に持ったまま再開します(手元から取った時点は記録に残らないため)。誤差の方向は「動きが増える」側であり、検知されない結末を過大に見せることはありません。

**再実行の結果**(`runs/deviation_tree_fixed_20260728`、8世界、7日間、2階層):

| 深さ | 生成された操作 | 結末 |
|---|---|---|
| 1段目 | 申込を強行提出 | 判定できず |
| 1段目 | 本人確認を済ませたことにする | システムが拒否(販売担当の権限外) |
| 1段目 | 対応記録だけ先に残す | 判定できず |
| 2段目 | 本人確認を済ませたことにする | システムが拒否 |
| 2段目 | 検証を飛ばして承認依頼を上げる | **統制で検知**(期限超過通知が発報) |
| 2段目 | 契約を完了させる | システムが拒否 |
| 2段目 | 本人確認を済ませたことにする | システムが拒否 |
| 2段目 | 申込を強行提出 | 判定できず |

**修正で何が変わったか:**

1. **分岐後の世界が実際に動くようになった。**1段目の2世界は分岐後48行/56行の記録を残し、連絡の配信・チャットでの相談・保留判断・契約完了・書面交付が発生しています(修正前は16行・配信ゼロ)
2. **「統制で検知」の結末が初めて出た。**承認依頼を出したまま期限を超えた世界で、期限超過通知が発報しました。修正前は一度も出ていません
3. **打ち切りは今回も報告されています**(「世界数の上限に達し、1候補を実行しなかった」)

**参考(探索的観察・所見ではありません).** 1段目の一方の世界で、別の案件(高齢の顧客の案件)が承認を得ないまま契約完了・書面交付まで進み、それに対して**同僚が3回にわたり手を止めて指摘していました**(「高齢者対応案件は販売管理者の承認が必須」「承認未取得のまま」)。これは投入した操作とは別の案件で自然に起きた出来事で、判定の対象外です。ただし、修正前の分岐世界では同僚がそもそも一度も動けなかったため、こうした指摘が観察され得ること自体が今回初めて確認できました。

**費用: 8世界+生成4回で約0.04クレジット。**
