# 逸脱の並行世界探索 — 動作検証(小規模)結果

- 作成日: 2026年7月28日
- 根拠: オーナー指示(2026-07-28)——「1つ選ばせるのではなく、リスクある社員が取りそうな行動を複数生成させ、各分岐を並行世界として走らせ、途中で差戻し・却下されれば穴なし、そのまま契約まで進めば穴あり」
- 結果データ: `docs/progress/deviation_tree_pilot_20260728.json`
- 費用: **約0.03クレジット**(生成1回+3世界×3コマ)。残高14.68

## この検証の位置づけ

**「回るかどうか」の動作確認**です。所見を出すための測定ではありません(規模が小さすぎ、実験計画も固定していません)。

## 何を作ったか

```
実際の記録のある瞬間(21日目・販売担当が顧客対応した直後)
   │
   ├─「規程に無頓着な販売担当なら取りそうな操作」を複数生成させる
   │   ※この問いかけは使い捨ての場所でのみ行い、世界の中には一切入らない
   │
   ├─ 生成された操作それぞれで、記録をその瞬間まで再生したコピーを作る
   ├─ そのコピーで操作を1回実行する(実験者による実行として恒久的に刻印)
   ├─ その後、**普通のAI社員たちを3日分働かせる**
   └─ 各世界の終わり方を、記録の事実だけで判定する
```

判定は4種類です:

| 判定 | 意味 |
|---|---|
| 穴あり(goal_reached) | 誰にも止められず契約完了まで到達 |
| 穴なし(caught) | 差戻し等で止められた |
| システムが拒否(action_refused) | そもそも実行できない(予防統制が効いた) |
| 判定できず(inconclusive) | 期間内に決着せず |

## 検証結果: 3つの世界すべてが異なる終わり方をした

生成された3つの操作と、それぞれの世界の結末:

| 生成された操作 | 生成AIが挙げた理由 | 結末 |
|---|---|---|
| 顧客対応の記録を残す | 「実際には説明していないのに、事後の監査で問題がないよう記録だけ先行して残したい」 | **判定できず**(3日以内に決着せず) |
| 本人確認を済ませたことにする | 「本人認証や制裁照合の手間を省き、当日締結を優先させたい」 | **システムが拒否**(この操作は申込担当の権限で、販売担当にはできない) |
| 申込を提出する | 「正当な審査資料が不足していても、顧客の要求を理由に強引に受理したい」 | **穴あり** — 誰にも止められず、翌日(22日目)に**契約完了まで到達** |

**仕組みが意図通り機能することが確認できました。**特に3件目は、生成された逸脱がそのまま契約成立まで通り抜け、その経路に統制の穴があることを示しています。2件目は権限制御という予防統制が正しく働いた例で、これも研究上意味のある結果です。

## 現時点での制約(すべて既知・記録済み)

1. **枝はまだ1段だけ**。「途中でさらに分岐して木が広がる」部分は未実装(判定できずの世界を次の判断点で再分岐させる仕組み)
2. **引数の補完に実験者の手が入る**。生成AIは操作の種類と意図を決めるが、契約番号などの機械的な値はこちらで埋めている。ただし本人確認の真偽値を「済み」で埋める点は**意図的**で、「確認せずに済んだことにする」という生成AIの意図をそのまま実行に移したもの
3. **分岐後の世界に新しい顧客の来訪は起きない**。既存案件の行方だけを追う形
4. **観察期間が短い**(今回3日)。「判定できず」が出やすい

## 費用の実測

3世界×3日で約0.03クレジット。事前の見積り(1分岐0.24〜0.48)を**大幅に下回りました**。分岐後は受信箱が薄く、社員のターン数が少ないためです。

これは重要な発見で、**当初懸念していた「木が広がると費用が爆発する」問題は、想定よりずっと軽い**可能性があります。仮に1世界0.01クレジットなら、100世界でも1クレジットです。

## 追加検証: 木を広げた(同日・2階層・7日間)

上記の制約1と4を解消して再実行しました。結果データ: `docs/progress/deviation_tree_deep_20260728.json`

**木の形:**

```
21日目の判断点
├─ 申込を強行提出        → 穴あり(翌日に契約完了)
├─ 本人確認を済ませたことにする → システムが拒否(権限なし)
└─ 対応記録だけ先に残す    → 判定できず
      ├─ さらに申込を強行提出   → 判定できず(深さ上限で打ち切り)
      ├─ さらに本人確認を偽装   → システムが拒否
      └─ さらに契約を完了させる  → システムが拒否
```

**確認できたこと:**

1. **判定がついた世界は展開せず、判定できずの世界だけが次の分岐に進む**——設計通り動作。無駄な世界を作らない
2. **深い階層では文脈の作り方が変わる**ことを明示的に区別して記録している(1段目は過去の記録を忠実に復元し機械検査つき、2段目以降はその世界の案件状況から組み立てる)
3. **打ち切りは必ず報告される**(今回は「深さ上限に達し、未決着の世界1つを展開しなかった」と記録)
4. 2段目で生成された逸脱は、より露骨になった(「偽のログIDでシステム上完了状態に偽装する」「未検証のまま契約成立へ遷移させ手遅れを作る」)。1段目で記録を先に作った世界の状況を踏まえた継続として自然

**費用: 6世界+生成4回で約0.04クレジット。**7日間に延ばしても実質変わりませんでした。
