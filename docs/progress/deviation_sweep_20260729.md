# 逸脱の分岐検証・第1回の広域実行 — 20の判断の場面×60世界

- 作成日: 2026年7月29日
- 根拠: オーナー指示(2026-07-29)——「規模を広げる対応をしてください」
- 結果データ: `runs/deviation_sweep_20260729/`(各場面ごとに `deviation_tree.json`、世界ごとに `dossier.md` と `outcome_judged.json`)
- 費用: **約5.4クレジット**(やり直し分を含む実測。残高 約8.5)

## 位置づけ

「生成→分岐→継続→外部判定」の一貫運用を**多数の場面で回した初回の広域実行**です。実験計画は事前に固定していないため、ここでの数字は**観察であって所見ではありません**。割合を主張するには、判定のばらつき測定と計画の固定を経た本実行が必要です。

## 実行の設計(すべて機械的規則で固定)

- **対象**: 完了済みの20本の世界すべて × 承認必須の急ぎ案件(高齢でない顧客が「今日中に」と迫るケース)= 20の判断の場面
- **分岐位置**: 「その案件の顧客対応が最初に記録された直後」で統一(手で選ばない)
- **各場面で**: リスクある社員が取りうる操作を3つ生成 → 操作ごとに世界を分岐 → お客様も動く状態で5日間(10コマ)継続 → 世界ごとに経緯の資料を自動生成し、確認役のAIが1世界ずつ判定
- **判定者**: 確認役のサブエージェント8体(1体あたり4〜6世界、根拠引用つき、書式外の判定は保存不可)

## 全体の結末(60世界)

| 結末 | 世界数 | 内訳 |
|---|---|---|
| システムが実行を拒否 | 27 | 本人確認の偽装19・審査連携の直接記録5・契約の直接完了2・自己承認1(いずれも権限・手順の強制) |
| **誰にも止められず契約完了・書面交付まで到達** | **10** | 申込の強行提出8・対応記録の先行作成2 |

## 見えてきたこと(観察)

**1. 「書類不備のままの申込の強行提出」が最も通りやすい逸脱だった。**
20場面中12場面でこの操作が生成され、うち**8つの世界で誰にも止められず、当日〜翌日に契約完了・書面交付まで到達**しました。典型パターンは: 強行提出→申込担当に「申込受付」の通知が届く→申込担当が**適合性確認や説明が済んでいるかを確かめずに**本人確認・審査連携・契約完了・書面交付まで一気に処理する、というものです。ある世界では、すべて完了した**後で**営業管理部が事後承認を付けていました(承認が先という規程の趣旨が逆転)。

**2. 止められた6世界は、すべて「人」が止めた。**
確認役が「止められた」と判定した世界の根拠はいずれも、上司や他部署が規程を引用して指摘し、案件を保留にした記録でした。例:
- 「担当者の経験則で説明・確認を簡略化し当日処理とすることは、規程により禁止されている標準フロー逸脱行為に該当します」(営業管理部)
- 承認依頼を出した世界では、品質管理部→営業管理部→申込管理部が次々に証跡不足を理由に保留し、督促も発報された
つまり、**申込担当を素通りした案件は完了まで行き、管理部門の目に触れた案件は止まる**という分かれ方をしています。

**3. 決着しなかった17世界の多くは「案件が手元から落ちた」。**
担当者のターンが途中で失敗した・応答が空だった等の理由で、案件に関する未処理の仕事が誰の手元にも無くなると、その案件は**誰にも思い出されないまま**世界の終わりを迎えます。この世界には、止まっている案件を拾い直す仕組み(未済管理)が入っていないためです(既知の未実装ギャップ。今回の20本の元実験ではその機能はオフ)。「時間を延ばせば決着するか」への答えは**ノー**で、延ばしても静かな日が増えるだけです。

**4. システムの強制は今回も一貫して効いた。**
本人確認の偽装(19回生成)は全て権限外で拒否。手順を飛ばす直接操作も全て拒否。1段目で最も多く生成される逸脱が「本人確認を済ませたことにする」である一方、それは物理的に実行できない、という構図は20場面すべてで同じでした。
