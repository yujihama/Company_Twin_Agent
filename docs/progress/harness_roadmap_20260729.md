# 統制の穴の自動検査ハーネス — ロードマップ

- 作成日: 2026年7月29日
- 根拠: オーナー指示(2026-07-29)——「最終的には、対象の業務プロセスの規程やマニュアル類を投入して、このハーネスを使って穴の有無を自動で検査させる使い方をしたい。ロードマップを策定してほしい」

## ゴール像(最終的な使い方)

```
入力: 検査したい業務プロセスの規程・マニュアル・様式の一式
   ▼
①組み立て: 文書から模擬の業務環境を自動で組み立てる
   (登場する役割、業務の流れ、システムが強制している手順、
    人が守るべきだが破れるルール、来訪するお客様・取引の類型)
   ▼
②通常運転: AI社員に普通に業務をさせ、業務が回ることを確認する
   ▼
③分岐検査: 各判断の場面で「リスクある社員が取りうる操作」を生成し、
   操作ごとに世界を分岐して自由に動かし、確認役が結末を判定する
   ▼
出力: 穴のレポート
   「どの操作が、どの経路で、何に止められたか/止められなかったか」を
   記録の引用つきで一覧化。止められなかった経路=設計上の穴の候補
```

**この検査が言えること・言えないこと(製品としての約束)**
- 言えること:「この規程と業務設計の下では、この操作がこの経路で誰にも止められない」という**設計上の穴の実在と形**(再現手順つき)
- 言えないこと: 穴の**網羅**(見つからなかった=無い、ではない)。実在の従業員がその操作を**する**という予測(発生確率は別の問い)

## 現在地(2026-07-29時点で動いているもの)

- 模擬の金融会社1ドメイン(販売プロセス、文書50点・意図した欠陥12箇所・AI社員7役・お客様38類型)
- 検査の心臓部は完成: 生成→分岐→(お客様も動く)継続→資料化→確認役の判定、が一貫で回る
- 第1回広域実行済み: 20の判断の場面×60世界。素通り10・人が止めた6・システムが拒否27・決着せず17
- 費用実測: 1場面(3分岐・5日間観察)あたり約0.22クレジット

## 第1段階: 検査機能を仕上げる(今の模擬会社のまま)

今の環境を使い、検査そのものの信頼性と網羅性を上げる。**環境が既知なので、答え合わせができる**のがこの段階の強み。

| # | 項目 | 内容 | 完了の条件 |
|---|---|---|---|
| 1-1 | 判定の安定性測定 | 同じ資料を確認役に複数回・複数モデルで判定させ、一致率を測る。ぶれる資料の型を特定し、資料の書式か判定の問いを改善 | 一致率の実測値が文書化され、不一致の型に対処済み |
| 1-2 | 検査範囲を全案件・全工程へ | 今は1類型の案件×「顧客対応直後」のみ。全案件類型×業務の各段階(受付後・本人確認後・審査後…)に分岐位置の機械的規則を広げる | 1本の世界から数十の判断の場面が自動列挙される |
| 1-3 | 複数手の逸脱 | 今は1操作のみ差し込む。「記録を作ってから提出する」等の連続手も生成・実行できるようにする(高齢のお客様の案件の穴はこれが無いと届かない) | 2〜3手の逸脱が分岐で実行され判定される |
| 1-4 | 木の自動展開 | 決着しなかった世界の再分岐(2段目以降)を、判定→次の分岐まで含めて自動で回す | 人手の介在なしに深さ2まで完走 |
| 1-5 | 穴レポートの自動生成 | 世界ごとの判定を「操作×経路×止めたもの」の一覧に自動整理。素通り経路には再現手順と記録の引用を添付 | 広域実行の結果からレポートが自動生成される |
| 1-6 | **答え合わせ(この段階の関門)** | 意図して仕込んだ12箇所の欠陥のうち、この検査で**いくつが素通り経路として再発見されるか**を測る | 検出できた欠陥・できなかった欠陥と、その理由が文書化される |

概算費用: 1-1〜1-5の開発は費用ゼロ(全て模擬実行で検証)。1-6の本実行は規模による(全案件×全工程なら数百世界。1世界0.05〜0.1として10〜30クレジット。実行前に見積りを提示)。

## 第2段階: 規程から世界を自動で組み立てる(新しい規程を入れられるように)

今の環境は文書50点に合わせて**手作り**した部分が多い(業務の流れの定義、役割の設定、システムが強制する手順の選定、お客様の類型)。ここを「文書を入れたら組み上がる」に近づける。

| # | 項目 | 内容 | 完了の条件 |
|---|---|---|---|
| 2-1 | 業務の流れの自動抽出 | 規程・マニュアルから、業務の段階・担当・必要な記録を読み取り、業務の地図を生成 | 人が地図を確認・修正できる形で出力される |
| 2-2 | 「システムが強制」と「人が守る」の仕分け | 各ルールを「システム改修なしには破れない」か「人がその気になれば破れる」かに仕分ける。**ここは人の確認を必須にする**(誤ってシステム強制にすると、観察したい逸脱が最初から起きない) | 仕分け案の自動生成+人の承認記録 |
| 2-3 | 役割・お客様の自動生成 | 役割ごとの業務説明と、来訪するお客様・取引の類型を文書から生成 | 生成物の品質検査(実験の気配が漏れていないか等、既存の検査機構を流用)に合格 |
| 2-4 | **第2ドメインでの通し試験(この段階の関門)** | 販売以外の業務(例: 保険金支払、融資審査、購買)のダミー規程一式を用意し、欠陥を仕込み、**組み立て→通常運転→分岐検査→答え合わせ**を通す | 手作りしていないドメインで、仕込んだ欠陥が検査で再発見される |

第2ドメインの通し試験は本実行を含むため、規模と費用を設計時に見積り提示。

## 第3段階: 一括自動検査と実規程での試行

| # | 項目 | 内容 | 完了の条件 |
|---|---|---|---|
| 3-1 | 一括実行 | 「文書一式→穴レポート」までを一つの手順で実行できるようにする(途中の人の確認ポイントは明示的に停止) | 第2ドメインで一括実行が通る |
| 3-2 | 人の確認ポイントの確定 | 人が必ず見る箇所を固定: ①強制/規範の仕分け ②組み上がった世界の妥当性 ③穴レポートの解釈(実務上意味のある穴か) | 確認手順書 |
| 3-3 | 実規程での試行 | 実在の業務プロセスの規程で試行(機密の扱いは別途設計: 実行環境・データの置き場所・モデル提供元の選定) | 試行レポートと、実務者による穴の妥当性評価 |

## 横断して守ること

1. **答え合わせを信頼の土台にする**: 「仕込んだ欠陥を何割再発見できるか」を段階ごとに測り続ける。これがこの装置の性能表示になる
2. **穴の判定は常に記録の引用つき**: 確認役の判定は根拠の引用が必須(実装済み)。レポートも同じ規律で作る
3. **限界の明示**: 網羅の保証はしない・従業員の行動予測ではない、をレポートの定型文にする
4. **費用の事前提示**: 本実行は規模と概算を先に提示してから(現行ルールの継続)
5. **逸脱候補の生成に規程は見せない**(今回確認した方針): 不正はルールを把握せず起きるものだから。規程は世界の組み立てと、社員・確認役の側だけが使う

## 直近の着手順(第1段階の中)

1. **1-1 判定の安定性測定**(費用ほぼゼロ・全ての土台)
2. **1-5 穴レポートの自動生成**(今回の60世界の結果がそのまま試験データになる)
3. **1-2 検査範囲の拡大**と**1-3 複数手の逸脱**(高齢のお客様の案件の穴に届かせる)
4. **1-6 答え合わせ**の本実行(規模・費用を見積もって承認後)
