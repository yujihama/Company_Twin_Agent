## 実行の設計(すべて機械的規則で固定)

- **土台**: 元の20本の世界一式はどの版にも収録されていないことを全履歴・全PRの中身で確認したうえで、収録済みの分岐世界の記録に一字一句そのまま埋め込まれている「分岐位置(31コマ目)までの元の記録」を取り出して土台にした(改ざん検知の連鎖を検査し、実行条件の再構成が20世界すべてで記録と一致することを確認。出どころは各土台世界の provenance.json)
- **範囲**: 仕込んだ欠陥に結び付く9種類の検証用ケース × 全工程(顧客対応・申込受付・本人確認・審査連携・承認・契約完了の各直後)の30組合せ × 状況違い2本まで = 47場面。選定は一覧に固定し、実行順は「全30組合せを1本ずつ→その後に2本目」とした(上限で止まっても組合せの取りこぼしが出ない順)
- **各場面**: リスクある操作を生成(最大3手の連続操作も可)→ 操作ごとに世界を分岐 → お客様も動く状態で10コマ継続 → 確認役が世界ごとに判定
- **実行**: 3本並行。途中成果は約30分ごとにリポジトリへ退避。47場面すべて実行され、費用上限による打ち切り・実行失敗はゼロ

**再発見 0 / 部分的 0 / 再発見されず 12(全12箇所)**

判定理由は12件を通して一貫している: 素通りした7経路の機序は資料上すべて「差し込んだ操作の後、
通知を受けた後続の担当部署が、確認せずに本人確認→審査連携→契約完了→書面交付まで機械的に

## この結果が意味すること(率直に)

1. **装置の主出力は機能している。** 素通り経路7件はすべて、判定理由・記録の引用・再現手順つきの
   個別の事実として特定できた。検査範囲の拡大(全工程・複数手・高齢のお客様のケースを含む
   9種類)も機械的規則どおりに動いた
2. **「規程の欠陥 → 素通り」の橋は、範囲を広げても架からなかった。** 前回の試運転の結論
   (機序は今の資料からは特定できない)は、範囲を広げた本実行でも変わらなかった。素通りの
   原因が資料上「後続部署の機械的処理」に集中しているためで、規程を読んで迷う・規程の穴を
   使うという行動自体が素通り経路の記録に現れない
3. 橋を架けるには、次のどちらか(または両方)が要る——**オーナー判断事項**:
   - 確認役が判定時に、世界の全記録・規程本文まで遡って機序を照合できる形にする(前回、
     将来課題として記録済み。生成側に規程を見せない方針は維持できる)
   - 欠陥に照準した逸脱の生成(ただし生成側に規程を見せない現方針との両立が論点)

## 観察された注目点(個別の事実。引用と再現手順は穴レポートに)

1. **「保留」が実行を止めない。** 担当者が案件を保留と記録しても、同じコマの内に後続部署が
   契約完了・書面交付まで処理し切る経路が複数あった(保留は記録上の宣言であって、手続を
   物理的に止める装置ではない)。素通り7経路の主因のひとつ
2. **高齢のお客様のケースでも素通りが発生。** 本人確認の直後に契約完了を強行した世界で、
   誰にも止められず書面交付まで到達した(ただし答え合わせの判定のとおり、「高齢の定義不在」
   という欠陥が通り道になったと資料からは言えない)
3. **止められた4経路は、すべて「人」が規程を引用して止めた。** 前回の広域実行と同じ構図
4. **複数手の逸脱(2〜3手)は大半がシステム拒否。** 119件の拒否の多くは、権限外の操作を含む
   連続手で、1手目または途中の手で止まっている(何手目で・なぜ止まったかは記録に残る)
